# خطة استكمال التكامل الشامل وفصل الشريط الجانبي وتدقيق المحركات المحاسبية (NOVARO ERP)

تهدف هذه الخطة إلى معالجة شقين رئيسيين: أولاً، فصل هيكل التمرير للشريط الجانبي (`AppSidebar`) عن لوحة العمل الرئيسية بحيث يتحرك كل منهما باستقلالية تامة مع تثبيت الرأس وإضافة بحث فوري للوحدات؛ وثانياً، إغلاق كافة الفجوات الهندسية في المحركات المحاسبية والتشغيلية وربط الواجهة بقاعدة البيانات المحلية المدمجة (`PGlite`) عبر طبقة مزامنة مزدوجة، مع توثيق واختبار كافة التدفقات آلياً.

---

## 1. فصل حركة الشريط الجانبي وهندسة إطار العمل (Viewport Layout Decoupling)

### لماذا كانت الواجهة تتحرك بالكامل مع الشريط الجانبي؟
كان الحاوي الجذري للتطبيق يعتمد على ارتفاع متمدد (`min-h-screen`) بدلاً من إطار مقفل على ارتفاع النافذة (`h-screen overflow-hidden`). يؤدي ذلك إلى تمدد جسم الصفحة (`document.body`) مع طول القائمة الجانبية، فعند تمرير عجلة الفأرة فوق الشريط الجانبي تنتقل حركة التمرير إلى النافذة الكلية (Scroll Chaining).

### الحل المعماري لتثبيت الإطار وفصل التمرير
* **قفل إطار العرض الكلي (Viewport Lock)**: ضبط الغلاف الرئيسي للتطبيق ليكون بارتفاع ثابت مطابق للشاشة (`h-screen overflow-hidden flex flex-col`) بحيث يظل الشريط العلوي (`Top Header`) وشريط الحالة السفلي ثابتين في مكانهما دائماً.
* **عزل التمرير في الشريط الجانبي (`overscroll-contain`)**: منح الشريط الجانبي ارتفاعاً كاملاً ضمن منطقة العمل (`h-full overflow-y-auto overscroll-contain shrink-0`) لمنع انتقال حركة العجلة إلى المحتوى المجاور حتى عند الوصول إلى نهاية القائمة.
* **بحث سريع وتصفية فورية في الشريط الجانبي**: تثبيت حقل بحث سريع في أعلى الشريط الجانبي (`sticky top-0`) يتيح للمستخدم تصفية أكثر من 60 شاشة ووحدة فرعية بالاسم العربي أو الإنجليزي لحظياً مع زر لتوسيع أو طي كافة المجموعات بضغطة واحدة.
* **استقلالية منطقة العمل المركزية**: ضبط لوحة العمل الرئيسية لتكون (`flex-1 h-full overflow-y-auto overscroll-contain`) بحيث تتمرر الجداول والتقارير الطويلة داخلها فقط دون التأثير على القائمة الجانبية أو الرأس العلوي.

## 2. المعمارية التفاعلية والمزامنة المزدوجة مع قاعدة البيانات المحلية (PGlite)

```
+-----------------------------------------------------------------------------------+
|                        واجهة المستخدم الثابتة (h-screen)                           |
|  +-----------------------+  +--------------------------------------------------+  |
|  | الشريط الجانبي المستقل |  |           منطقة العمل المركزية المستقلة           |  |
|  | - بحث فوري مثبت       |  | - شريط الإجراءات الموحد (GlobalActionBar)        |  |
|  | - تمرير معزول         |  | - الجداول المالية والتقارير والنماذج             |  |
|  +-----------------------+  +--------------------------------------------------+  |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                    مدير الحالة الموحد (StateContext & Persistence)                 |
|  - تخزين لحظي متزامن في المتصفح (LocalStorage Snapshot)                           |
|  - جسر مزامنة مزدوج الاتجاه (Bidirectional Sync Engine) مع الخادم المحلي          |
+--------------------+-----------------------------------------+--------------------+
                     |                                         |
                     v                                         v
+----------------------------------------+   +--------------------------------------+
|     محركات النطاق المحاسبية والرقابية  |   |   قاعدة البيانات المحلية (PGlite SQL) |
| - محرك القيود المزدوجة وإقفال الفترات  |   | - 31 جدولاً علائقياً عبر Drizzle ORM  |
| - محرك المخزون والتصنيع متعدد الطبقات  |   | - وحدة العمل الذرية (UnitOfWork)     |
| - محرك الزكاة (ZATCA Phase 1 & 2)      |   | - جاهزية الترقية الفورية لـ Postgres |
| - مدقق تطابق الأستاذ الفرعي مع العام   |   | - نقاط نهاية API للمزامنة الشاملة    |
+----------------------------------------+   +--------------------------------------+
```

### آلية المزامنة المزدوجة (Bidirectional State & PGlite Sync)
* **لماذا المزامنة المزدوجة؟**: تضمن استجابة فورية (Zero-Latency) في الواجهة الأمامية مع حفظ علائقي كامل داخل محرك SQL المحلي (`PGlite`) بحيث تعمل التقارير الخلفية واختبارات التكامل على نفس البيانات الحقيقية.
* **نقطة نهاية المزامنة الشاملة (`/api/v1/sync/snapshot`)**: إضافة مسار خلفي يقوم باستقبال وتصدير الحالة المحاسبية والتشغيلية الكاملة (الحسابات، القيود، الأصناف، الدفعات، طبقات التكلفة، العملاء، الموردين، الفواتير، وأوامر التصنيع) داخل معاملة ذرية (`UnitOfWork`) في `PGlite`.
* **مؤشر المزامنة والتحكم اليدوي والتلقائي**: ربط شاشة حالة المزامنة (`admin_sync_status`) وشريط الحالة بإجراءات فعلية للمزامنة الفورية مع `PGlite` واسترجاع النسخ منها، مع تسجيل كل عملية مزامنة في سجل التدقيق (`AuditLog`).

## 3. استكمال وتدقيق المحركات المحاسبية والتشغيلية الأربعة

### أ. مطابقة الأستاذ الفرعي مع الأستاذ العام (Subledger-to-GL Reconciliation)
* **الهدف المحاسبي**: منع أي انحراف بين أرصدة بطاقات العملاء والموردين والمخزون وبين حسابات المراقبة في شجرة الحسابات.
* **التنفيذ**: توسيع محرك `DataIntegrityChecker` ليقوم بفحص آلي صارم يثبت أن:
  1. مجموع أرصدة العملاء يطابق رصيد حساب الذمم المدينة (`1200`).
  2. مجموع أرصدة الموردين يطابق رصيد حساب الذمم الدائنة (`2000`).
  3. مجموع تقييم طبقات المخزون (`FIFO Cost Layers`) يطابق مجموع حسابات المخزون (`1300` خام + `1310` محمص + `1320` مطحون/جاهز).
* **إصلاح ذاتي وتنبيه رقابي**: توفير أداة إعادة بناء ومطابقة الأرصدة (`reconcileSubledgers`) من واقع القيود المرحّلة وحركات الدفعات لضمان تطابق 100%.

### ب. محرك تكاليف التصنيع والتحميص والطحن متعدد المراحل (Multi-Stage Manufacturing FIFO)
* **الهدف التشغيلي**: تتبع انتقال التكلفة الفعلية من البن الأخضر الخام إلى البن المحمص ثم المطحون والمعبأ بدقة محاسبية.
* **التنفيذ**:
  1. التأكد من أن أوامر التحميص (`RoastingJob`) والطحن (`GrindingJob`) والتعبئة (`PackagingJob`) تستهلك أقدم طبقات التكلفة (`FIFO`) وتضيف المصاريف الصناعية المباشرة وتنشئ طبقة تكلفة جديدة (`CostLayer`) للدفعة الناتجة.
  2. توليد قيد يومية آلي متوازن يخفض حساب مخزون المواد الخام/نصف المصنعة ويزيد حساب مخزون الإنتاج التام مع إثبات تكلفة الفاقد أو الهدر الطبيعي.

### ج. ترحيل المرتجعات وإشعارات الزكاة الدائنة والمدينة (Returns & ZATCA Credit/Debit Notes)
* **الهدف الضريبي والمحاسبي**: ضمان معالجة مرتجعات المبيعات (`381 Credit Note`) ومرتجعات المشتريات (`383 Debit Note`) محاسبياً ومخزنياً وضريبياً.
* **التنفيذ**:
  1. استكمال دوال المرتجعات في `CommerceService` و`StateContext` لعكس الأثر المالي في الذمم والضريبة، وإعادة الكميات المرتجعة إلى طبقات المخزون بتكلفتها الأصلية، وعكس قيد تكلفة البضاعة المباعة (`COGS`).
  2. ربط كل مرتجع مبيعات بمحرك `ZatcaEngine` لتوليد إشعار دائن إلكتروني (`InvoiceTypeCode: 381`) مرتبط برقم الفاتورة الأصلية وسلسلة التشفير المتسلسلة (`PIH` و`ICV`).

### د. إقفال الفترات والسنوات المالية وإهلاك الأصول ومسير الرواتب (Period Lock, Year-End, Assets & Payroll)
* **الهدف الرقابي**: حماية الفترات المغلقة من أي تعديل أو ترحيل عكسي، وأتمتة قيود التسوية الدورية.
* **التنفيذ**:
  1. تطبيق حارس الفترات المالية (`FiscalPeriodGuard`) على كافة العمليات (فواتير، مرتجعات، سندات خزينة، تصنيع، رواتب، إهلاك) لرفض أي عملية تقع في فترة مغلقة.
  2. تدقيق محرك إقفال السنة المالية (`closeFiscalYear`) لتصفير كافة حسابات الإيرادات (`4xxx`) والمصروفات (`5xxx`) وترحيل صافي الربح أو الخسارة إلى حساب الأرباح المبقاة (`3100`).
  3. التحقق من القيود الآلية لإهلاك الأصول الثابتة (`5400` مصروف إهلاك إلى `1510` مجمع إهلاك) واعتماد مسير الرواتب (`5200` مصروف رواتب إلى النقدية/البنك).

## 4. توسيع حزمة الاختبارات والشهادات الآلية (Automated Certification Suite)

* تحديث حزمة الشهادات المدمجة في النظام وملفات الاختبار لتشمل:
  1. اختبار عزل التمرير ومطابقة هيكل الواجهة.
  2. شهادة التصنيع متعدد المراحل (`Manufacturing FIFO & WIP Rollup Certification`).
  3. شهادة المرتجعات والإشعارات الضريبية وسلسلة هاش الزكاة (`ZATCA Chain & Credit/Debit Note Certification`).
  4. شهادة مطابقة الأستاذ الفرعي مع الأستاذ العام (`Subledger-to-GL Control Account Certification`).
  5. شهادة المزامنة المزدوجة مع قاعدة البيانات المحلية `PGlite`.
